# ZPlace Studio v19.0.0

V19 packages the browser Studio and the completed V18.6 performance work.
Python and the web assets are bundled in the EXE; users do not need Node.js.

## Update and start

1. Stop the previous Studio using its shutdown control. Closing the browser or log window does not stop the server.
2. Back up your existing Studio data folder.
3. Extract `ZPlace-Studio-update.zip` into that same folder, or put the standalone V19 EXE there.
4. Run `ZPlace Studio v19.0.0.exe`. The browser opens at http://127.0.0.1:5000/studio/.

Do not run the old and new executables against the same data at the same time.
Existing data formats and browser preference keys are preserved. The update archive contains only the executable, not accounts, keys, artwork, queues or caches.

## Included changes

- Browser-based Studio with streams, masks, account controls and the existing tools.
- Map recording opens Microsoft Edge in a dedicated persistent profile and logs captured native tiles, skips and errors across its tabs.
- Extraction uses a fast overview followed by a fixed native-resolution area of up to 3x3 game tiles. Zoom and pan do not reload or degrade that area.
- Compressed pixel responses, bounded server/browser caches, worker raster reuse and fewer redundant library refreshes.
- Maps no longer enter the JSON artwork catalog. Drafting a mask no longer reloads the full artwork.
- Independent Windows log window: closing or minimizing it does not stop Studio. Browser logs and explicit shutdown are available.
- UI, launcher and package version updated to 19.0.0. The older Python entry point forwards to V19.

## Userscripts

No userscript changes in this release. Current compatible versions remain PC `1.8.12-charge-pass` and mobile `1.7.11-mobile-charge-pass`. Mobile does not collect Overlay data. They are not included in the EXE-only update archive.

## Known Sync limitations

The Sync audit found eight reproducible issues. V19 does not claim to fix them: restart can block pending completion reports; partial completion can reissue old coordinates; two clients of the same user/account can share a reservation; concurrent art replacement can lose a revision; a snapshot can be labeled with a newer revision; deleted art can block release/disconnect; operation IDs are not scoped to actor/action; deleting a user with history can fail a foreign-key check.

The detailed audit is attached to this release as `SYNC-AUDIT-18.6.md`. These limitations concern collaborative Sync, not a newly changed protocol in V19.

## Validation scope

V19 passed 166 Python tests on isolated data and 23 userscript tests; the live queue was unchanged. The rebuilt EXE passed startup, embedded assets, conversion, account reception, read-only forecast and browser canvas checks with no page errors. The V18.6 baseline additionally passed packaged desktop/mobile UI checks, native image/extraction checks and controlled Edge capture. Local and controlled-response tests are not proof of live Wplace painting or purchases.
